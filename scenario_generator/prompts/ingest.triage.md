Nothing else will look at the documents for these questions. Whatever you cannot answer here goes
to a person, so for every question you mark `unanswered` you must also say which kind of leftover
it is. Use one of these two in place of `unanswered`:

- `ask_the_team` — the documents do not settle it, and not knowing it changes the testing. A
  branch whose outcomes are unstated, a threshold that decides between two behaviours, a rule the
  documents name without stating, a hand-off whose trigger is missing. Only the team that built
  the agent can supply these, and the benchmark is weaker without them.

- `not_material` — the documents do not settle it, and knowing it would not change which scenarios
  get written or how any of them is judged. Implementation detail, ownership, versions, wording,
  anything already adequately covered by a related answer, or a question the first reading raised
  more precisely than it needed to.

Judge these strictly and in both directions. Every `ask_the_team` costs a real person real days of
chasing, and a list long enough to be daunting is a list nobody works through — so a question that
does not earn its place crowds out one that does. But a question marked `not_material` is never
asked by anyone, and if it did matter, the gap it leaves is silently tested as though the agent's
behaviour there were known. When a question is genuinely borderline, mark it `ask_the_team`: the
cost of asking is an hour of someone's attention, and the cost of not asking is a benchmark that
tests something the agent does not do.
